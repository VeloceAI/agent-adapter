# WP16 — Google ADK (plan)

**Scope:** contract §14.4 row `adk`; §13.5 compile rules; exit gate in §21.3 (kit C1–C8 with a
scripted `BaseLlm`, confirmation approve / deny / payload edit, parity cases with ADK replay
de-duplicated by node path). Internals per R2 §3, §4, checked against google-adk 2.13.0 and
google-genai 2.34.0 (probes in this plan's commit message history, not in the repo).

## Verified ADK behaviour the design relies on

| Fact (2.13.0) | Consequence |
|---|---|
| `ctx.run_node(node, input, run_id="v1")` gives the child path `<parent>/<name>@v1`; numeric run ids are refused | deterministic child paths per node visit and attempt |
| A node re-run on resume fast-forwards every child that already produced an output (no re-execution), per invocation | the driver re-derives its position by replay; side effects run once |
| `ctx.resume_inputs` holds every answered interrupt of the node, across turns | the driver knows which pauses are answered |
| `invocation_id` is the same across resumes (resumable or not) | `run_id = invocation_id` (contract §8.2) |
| A child's exception propagates unwrapped out of `Runner.run_async` | `FlowError` / `FlowLoopExceeded` reach the caller as is |
| LlmAgent confirmation: `check_require_confirmation` → `adk_request_confirmation` call (random id, carries `originalFunctionCall`); the resume re-calls `run_async` with `tool_context.tool_confirmation` | the tool bridge reads only an adapter token from `payload` |

## Design

- **Tools** (`tools.py`): one `BaseTool` subclass per spec (class built lazily). Declaration =
  `to_gemini_parameters(spec.json_schema())`. `check_require_confirmation` = our confirm rule on
  validated arguments. `run_async` runs `runner.run_spec` with `bind_context(tool_context)`;
  `ctx.approval` is set **only** from a one-use adapter token (`payload == {"aa_token": …}`)
  bound to run (invocation id), native call id, tool and `request_digest`. ADK's `confirmed`
  alone never approves: without a token the executor asks its own port.
  `resolve_confirmations(events, port, registry)` asks the port with `approval.batch.ask_each`
  and returns the resume `Content` (tokens carry the decision, edits included).
- **Compile** (`compile.py`; `_workflow.py` ADK nodes and entry, `_driver.py` loop, `_steps.py` child work): `Workflow(edges=[(START, driver)])`. The driver
  replays the local runner's superstep loop (`flow._nodes.run_node`, `flow._step` merges,
  routes, edits). Every side effect or non-deterministic step is a child node with a
  deterministic run id, so a re-run driver fast-forwards it:

  | Child run id | Does | Output |
  |---|---|---|
  | `v{V}g{k}` | gate: answer interrupt k−1 (token), else ask the port | decision or pending |
  | `v{V}` / `v{V}r{k}` | the node visit (first run / re-run after resume k) | updates + route labels, or pending + journal + items |
  | `v{V}a{k}` | answer tool interrupt k (token → settle in the store, spend once) | decision or refused |
  | `v{V}w{k}` | withdraw superseded records of pause k | ids withdrawn |

  Interrupts are `RequestInput` with the ToolConfirmation schema, id
  `aa:<session id>:<child path>`. A missing or invalid token re-asks the port (fail closed).
- **Resume** (`_tokens.py`): `resume_message(interrupt_id, decision)` issues a token for an
  interrupt this process raised (else none: the port decides on resume).
- **Run** (`_run.py`): `run_workflow(workflow, state | resume Content, ...)` → `FlowResult`;
  visits from this invocation's child paths, de-duplicated by path.

## Tasks (test first)

1. `_support.py`, `_tokens.py` + `tests/integrations/adk/test_tokens.py` (issue/take binding,
   one use, TTL, forged/edited payloads refused, `resume_message` shapes).
2. `tools.py` + `tests/integrations/test_adk_contract.py` (kit C1–C8 through `LlmAgent` with a
   scripted `BaseLlm`; C6 native via `resolve_confirmations`) + `tests/integrations/adk/
   test_tools.py` (forged confirmation, edited payload, DeferredApproval two-phase, foreign tools).
3. `_steps.py`, `compile.py`, `_run.py` + `tests/integrations/adk/test_compile.py` (shape,
   errors, events, run ids) and `tests/integrations/adk/test_parity.py` (every case of
   `tests/flow/parity.py`, compared with `assert_state_matches`; replay runs each node once).
4. `tests/integrations/adk/test_security.py`: forged / replayed / cross-run resume answers
   fail closed in compiled flows; store decided otherwise; double resume.
5. Docs `docs/integrations/adk.md` (Available, mermaid, parity table), `examples/adk_tools.py`,
   `examples/adk_flow.py` (run by the contract session); SHARED-EDITS (features rows,
   CHANGELOG, integrations index).
